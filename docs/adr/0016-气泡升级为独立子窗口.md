# ADR-0016：气泡升级为独立子窗口（原生跟随 + panel 分流）

- 状态：已采纳
- 日期：2026-06-18
- 关联：[ADR-0013：多窗口独立桌宠与协调者 / 呈现者模型](0013-多窗口独立桌宠与协调者模型.md)、[ADR-0014：放弃全屏覆盖与动态窗口去 NSPanel 化](0014-放弃全屏覆盖与动态窗口去-nspanel-化.md)、[ADR-0015：鼠标穿透由原生独占](0015-鼠标穿透由原生独占与命中形状下发.md)
- 实现自：[多窗口独立桌宠 · Phase A 设计](../superpowers/specs/2026-06-17-多窗口独立桌宠-phaseA-design.md)

## 背景

ADR-0013 把每只 pet 拆成独立窗口后，气泡仍留在各自 pet 窗口内，靠窗口纵向增高 / 翻转 + 反锚点补偿承接（`getBubbleWindowLayout` / `computeWindowTop` / `petAnchorBottomY` / `shouldFlipStack` + CSS `--stack-below` / `is-flipped`）。这套布局是 Phase B 残留的最后一坨复杂度：每弹一条气泡就要 resize + 反向补偿宠物锚点，命中区上沿随之跳动，且气泡尺寸被 pet 窗口约束。

同时，`main` 当初被提升为自定义 `NSPanel`（`GoodPuppyPanel`）的**唯一理由**是让写消息记号棒的 textarea 能成为 key window 接收键盘（无边框窗口默认 `canBecomeKeyWindow` 为 NO）。这个 panel 语义（非激活面板 `becomesKeyOnlyIfNeeded`）带来 macOS first-mouse bug：失焦后第一次左键只用于激活面板、不派发到 webview，导致桌宠要点两次才能拖。

## 决策

**把气泡升级为独立透明子窗口，由 OS 让它跟随 pet 窗口移动；并据此把记号棒搬出 `main`、让 `main` 去 panel 化。**

- **每只 pet 配一个气泡子窗口**：自己 = `bubble-self`，远程 = `bubble-<userId>`，加载极简 `bubble.html`，只渲染该 pet 的消息堆叠（自己窗口另含记号棒）。
- **原生跟随（平台分叉）**：macOS 用 `[parent addChildWindow:child ordered:NSWindowAbove]`，OS 在 pet 移动（含原生拖动的模态循环、程序化 `setFrame:`）时自动带气泡同步、零延迟；Windows `set_parent` 只建 owner 关系不跟随，故监听父窗口 `WindowEvent::Moved` 按存储偏移重定位子窗口（前置 spike 项）。
- **panel 分流（延续 ADR-0014）**：只有 `bubble-self` 含可写 textarea，提升为 `GoodPuppyPanel`，且像 `main` 一样整会话只隐藏不销毁 → 不碰「销毁被提升 panel 即崩」雷区；远程气泡窗口是普通透明窗口，可随成员离线安全销毁，与远程 pet 窗口同构。
- **`main` 去 panel 化**：textarea 搬进 `bubble-self` 后，`main` 不再需要成为 key window，改走普通 `configure_floating_overlay`。配合已有 `acceptFirstMouse`，第一次左键即可拖动——修复 first-mouse bug。
- **pet 窗口固定 pet 尺寸**：删除纵向增高 / 翻转那套布局，pet 窗口只负责单 pet 动画 + 拖动 + 像素命中。气泡上/下避让退化为纯函数 `computeBubbleWindowPosition`（pet 几何 + 屏幕可用区 → 气泡窗口位置 + above/below），由协调者算出、气泡窗口自行 `setWindowBounds` 应用。
- **通信契约基本不动**（ADR-0013 已铺好）：`pet-state` / `pet-interaction` 仍投 pet 窗口；`pet-message` / `pet-history` 改投气泡窗口；新增 `bubble-placement`（几何 + 朝向）与自己写消息回环 `self-compose-submit` / `self-compose-result`（气泡窗口不碰 Supabase，提交回环到协调者，对齐 ADR-0004）。
- **光标监视器**纳入 `bubble-*` 窗口（各自下发命中形状 = 可见堆叠 / 记号棒矩形，无 pet 剪影掩模），对齐 ADR-0015。

## 后果

- **正面**：pet 窗口命中区 / 穿透上沿干净，绝不因弹气泡跳位；气泡可自由浮出 pet 边界、尺寸不受 pet 窗口约束；退役了 Phase B 最后一坨布局复杂度；first-mouse 拖动 bug 修复；自己 pet 与远程 pet 的窗口配置自此完全对称（均普通浮动窗口，panel 仅 `bubble-self`）。
- **负面 / 成本**：窗口数翻倍（每 pet 多一气泡窗）→ 光标监视器负载约 2N；跟随机制平台分叉（macOS 免费，Windows 需 `Moved` 重定位 + spike）；多屏下气泡上/下避让用 `main` 所在屏可用区做近似，副屏 pet 的翻面判定可能略偏（智能避让属 YAGNI）。
- 写消息提交多了一跳跨窗口回环（`bubble-self` → `main` → Supabase → 回报），但订阅 / 网络仍单一住在协调者，无新增竞态。

## 备选与权衡

- **沿用窗口内增高 / 翻转**：无新增原生复杂度，但保留每弹气泡 resize + 反锚点补偿的脆弱布局、气泡受窗口约束、命中上沿跳动；且无法把 textarea 搬出 `main`，first-mouse bug 无解。排除。
- **用 Tauri `set_parent` 代替原生 `addChildWindow`**：跨平台统一，但 macOS 下其语义与「自动跟随」不完全一致、且会重排 webview 层级，控制力弱于直接 objc2 调用。选原生以对齐既有 `lib.rs` 风格并确保跟手。

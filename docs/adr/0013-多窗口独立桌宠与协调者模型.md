# ADR-0013：多窗口独立桌宠与协调者 / 呈现者模型

- 状态：已采纳
- 日期：2026-06-17
- 取代：[ADR-0007：单窗口方案驱动 presence 渲染](0007-单窗口-presence-渲染.md)
- 关联：[Phase B 设计](../superpowers/specs/2026-06-17-多窗口独立桌宠-phaseB-design.md)、[Phase A 设计](../superpowers/specs/2026-06-17-多窗口独立桌宠-phaseA-design.md)

## 背景

ADR-0007 为 MVP 选择了**单窗口动态多 pet 渲染**：自己与所有远程成员的 pet 都画在同一个透明置顶窗口里。它在物理上无法让每只 pet 独立拖动——它们共享一个窗口，拖一个就拖全部，"桌面上散落着朋友们"的氛围感无法成立。

presence、亲密关系与在场感已在 MVP 验证成立，现在要补上 0007 主动延后的能力：**让同房间成员各自成为独立、可分别拖动的窗口**。0007 当年列出的多窗口复杂度（动态 capability、`NSPanel`/Space/层级、每窗口穿透与光标流、原生拖动协调）依然存在，但通过下面的「协调者 / 呈现者」架构被收敛到可控范围。

## 决策

采用**多窗口 + 单一协调者**模型（Phase B 落地）：

- `main` 窗口降级为「自己的 pet 窗口 + 房间协调者」，房间内常驻。
- 每个在线远程成员 = 一个动态创建的透明 `NSPanel` 窗口，label `pet-<userId>`，加载 `pet.html`，按窗口 label 进入「远程呈现者」模式。

### 命门：一份订阅，集中协调

绝不让 N 个窗口各自订阅同一房间的 presence/realtime。**协调者（自己窗口）独占所有 Supabase 订阅**：

- 订阅 presence / messages / interactions（沿用 `roomManager`）。
- presence diff → 调 Rust `spawn_pet_window` / `close_pet_window`。
- 用 Tauri `emit_to(label, …)` 把每只远程 pet 需要的数据定向转发：状态/皮肤/petId、消息（单条+历史）、被互动事件、退场、模式、自动排布坐标。
- 管理位置持久化（房间+成员 / self 全局）与「完全自由 / 半自由」模式。

**每个远程 pet 窗口是哑呈现者**，不碰 Supabase：收协调者事件 → 播动画、渲染气泡、处理自身拖动/穿透/像素命中，拖动结束把新位置上报协调者持久化。

### 复用一份单 pet 呈现器

自己窗口与远程窗口共用 `petPresenter`（单只 pet 的动画→图像、命中、穿透、气泡纵向布局/翻转、拖动）。每个 webview 是独立 document，故"文档级"助手天然只作用于本窗口这一只 pet——这正是把 0007 单窗口逻辑收敛成单 pet 呈现器的关键简化。

### 摆放模式（用户可切换，默认完全自由）

- **完全自由**：每窗口可原生拖动、按 (房间+成员) / self 记忆位置；spawn 时有存档则还原，无则自动摆位兜底。
- **半自由**：远程窗口禁用拖动，协调者沿自己 pet 右侧一字排开并定向下发坐标；自己的 pet 仍可自由拖。
- 开关存 preferences（`goodpuppy.petMode`），入口在自己 pet 右键菜单「朋友摆放」。

## 影响

- Rust 新增 `spawn_pet_window` / `close_pet_window`；`set_window_bounds` 抽出 `position_overlay_window` 供动态窗口复用；光标监视器与 `pet-drag-ended` 服务所有 pet 窗口（`main` + `pet-*`），lounge/login 除外；`default.json` capability 覆盖 `pet-*`。
- `configure_macos_overlay_level` 是"配置一次就忘"的纯函数，套到每个新窗口边际成本低——这化解了 0007 对"窗口数放大平台细节"的顾虑。
- 退役 `remotePets.ts`（同 document 增删远程 DOM）与 `petInteractions.ts`（同 document 双角色播放）；横向撑宽布局（`PET_SLOT_WIDTH` 等）随之删除。
- 气泡仍留在各自 pet 窗口内（纵向增高/翻转）。升级为独立子窗口见 Phase A 设计，留待多屏与动态生命周期踩实后再做。

## 备选与权衡

- **维持单窗口（0007）**：无法独立拖动，不满足核心诉求。
- **每窗口各自订阅 realtime**：重复订阅、状态竞态，明确排除。
- **气泡即刻升级为原生子窗口**：唯一新增原生复杂度，YAGNI，分到 Phase A。

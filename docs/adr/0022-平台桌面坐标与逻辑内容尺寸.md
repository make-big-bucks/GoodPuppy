# ADR-0022：平台桌面坐标与逻辑内容尺寸

- 状态：已采纳，本地验证通过；Windows Rust 交叉检查通过，实际链接/实机及双平台多屏验收待完成
- 日期：2026-10-02

## 背景

Tao 在 macOS 以窗口比例包装 AppKit 全局逻辑位置，在 Windows 返回全局物理位置。Windows 将每块屏幕原点分别除自身比例会产生重叠，跨屏后以窗口比例解释旧存档也不可靠。

## 决策

- 窗口位置、屏幕矩形、工作区和父子偏移使用平台桌面单位：Windows 全局物理像素，macOS 全局逻辑点。
- 窗口内容宽高保留逻辑单位。几何快照同时返回 `desktopScale`，布局将内容尺寸和间距换算到桌面单位；原生定位按目标屏设置实际尺寸。
- 创建和定位携带明确的 `coordinateSpace`；不接受与平台不符或未知的单位标记。未标记的旧原生调用仅保留兼容入口，新前端统一使用新协议。
- 位置存档使用 `desktop-physical-v2` / `desktop-logical-v2`。macOS 旧逻辑记录可读取；Windows 旧记录缺少原屏比例，回退自动摆位后写新记录。
- 命中形状、动画和 DOM 交互仍使用窗口局部逻辑坐标，不使用桌面位置推断像素。

## 后果与验证

桥接、宠物/气泡/提醒创建定位、自动布局、缩放底边保持、位置可见性与父子跟随采用同一契约，避免各模块自行猜测比例。单位换算、负坐标、跨比例布局及旧存档回归与 macOS 原生生命周期通过；真实混合 DPI、双向跨屏、拔屏和 Windows 运行证据仍是发布门禁，见 [坐标验收](../reviews/coordinate-contract.md)。

# ADR-0020：房间会话生命周期与跨窗口协议

- 状态：已采纳
- 日期：2026-10-01
- 关联：ADR-0004、ADR-0013、ADR-0016

## 背景

启动恢复、切房间、退出和注销可交错，迟到的查询与订阅不能继续修改新会话；窗口状态广播也不能作为某次操作的成功回执。

## 决策

- 房间操作有递增版本，并串行处理共享资源；退出和注销立即使旧版本失效。
- 认证用户与 client 使用捕获的会话上下文；注销清身份，频道由创建它的 client 释放。
- 等待消息、在线状态和互动频道就绪，并确认在线写入后，才提交当前房间；加载历史期间缓冲消息并按 ID 合并。
- 清理使用独立收尾，一项失败不阻断其它资源释放；失败向调用者传播。
- 正常退出软件保留上次房间但标记离线；“退出房间”和注销清除房间。
- 跨窗口状态广播与操作回复分开，回复携带请求 ID，具有失败、超时和取消结果。
- 动态窗口携带实例令牌，呈现者通过 ready 握手绑定协调者；数据按序发送并丢弃旧实例/旧协调者消息，不再用定时重发代替就绪。创建与销毁串行，房间失效取消旧准备，销毁回执后才允许同名重建。

## 后果

业务继续留在前端，Rust 只管理原生能力；增加生命周期交错测试，避免仅靠局部纯函数测试推断整体正确性。布局、消息缓存与窗口资源分别有明确所有者。

# ADR-0023：版本 tag 发布、签名自动更新与 macOS 公证

- 状态：已采纳（真实发布与升级验收待完成）
- 日期：2026-10-23

## 背景

分支触发的 Actions 临时安装包没有固定版本发布语义，也无法承担长期分发与应用内升级。GoodPuppy 需要覆盖 Apple Silicon、Intel 与 Windows x86_64，并在安装更新前清理房间在线状态。

## 决策

以 `v*` tag 固定发布提交，校验版本一致后构建 GitHub Release 草稿，人工验收后发布；版本来源为 package.json，脚本同步 npm 与 Cargo 锁文件。临时安装包保留手动入口。

发布后单独校验全平台产物与签名 key ID，原子推进 updates 分支上的 stable / preview 清单。版本只前进，公开 Release 不允许重打覆盖；稳定客户端不接收预发布版本。

会客厅独占更新交互和提示，自动检查但下载与安装分别由用户触发；Rust 仅封装 Tauri 更新器的系统安装、验签及进程重启能力，更新包和密钥不交给前端。安装重启复用既有的有界房间退出握手，不改变透明窗口层级和命中规则。

macOS 正式发布必须使用 Developer ID Application、hardened runtime、公证与 Gatekeeper 验证，最后对已装订 APP 的归档生成独立更新签名。Apple 证书和更新私钥存 GitHub Secrets，公钥经仓库 Variable 在编译时嵌入；本地无公钥构建禁用更新，保持可开发、可测试。

## 后果

发布需要一次性配置 Apple 凭据与独立更新密钥；公钥与客户端信任绑定，必须备份私钥。公开 Release 后才推进更新渠道，构建失败不会自动影响已安装客户端。无更新器的历史版本需手动安装一次；Windows Authenticode、私有分发服务不在本次范围。真实签名、公证及跨版本升级仍须在凭据齐全的 CI 与各平台实机完成验收，操作见 [README 的版本发布说明](../../README.md#版本发布)。

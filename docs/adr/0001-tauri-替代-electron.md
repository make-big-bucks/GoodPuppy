# ADR-0001：使用 Tauri 替代 Electron 作为客户端框架

- 状态：已采纳
- 日期：2026-06-05

## 背景

GoodPuppy 当前基于 Electron，打出的 DMG 约 112MB——其中资产仅 650KB，其余全部是 Electron 自带的 Chromium 运行时。对于一个"住在桌面上"的环境式（ambient）应用，这个体积带来两个问题：

1. **分发摩擦**：用户首次下载超过 100MB，对于一个小圈子产品的病毒式传播不友好。
2. **定位错位**：Electron 的包体信号给用户传递的是"重型应用"，与 GoodPuppy 的"轻量在场"定位相悖。

此外，Electron 要求随 app 打包一套完整的 Chromium，导致内存占用较高，与"透明置顶悬浮在桌面"的使用场景不匹配。

当前代码库仍处于早期原型阶段（双人写死、无用户系统），迁移成本处于历史最低点。

## 决策

采用 **Tauri**（Rust 主进程 + 系统原生 webview）替代 Electron。

职责划分：
- **Rust 主进程（薄）**：透明窗口、窗口置顶、点击穿透、系统托盘、窗口定位与多窗口生命周期管理。
- **前端 webview**：所有业务逻辑——Supabase 连接、presence 心跳、消息订阅、认证、pet 渲染与动画。

Rust 主进程不直接接触 Supabase，不持有业务状态。

## 后果

**正面：**
- 包体预计从 ~112MB 降至 ~10–20MB，降幅 80%+，显著降低分发摩擦。
- 使用系统 webview（macOS 上为 WKWebView），内存占用大幅减少。
- 现有 renderer 层（HTML/CSS/JS）可基本直接复用，前端迁移成本低。
- Rust 原生 API 对多窗口管理、点击穿透等桌面能力支持更直接。

**负面：**
- 引入 Rust 构建环境，团队需要具备基本 Rust 知识（仅限主进程薄层）。
- 不同平台的系统 webview 版本存在差异，CSS/JS 兼容性需要更谨慎。
- Tauri 生态相比 Electron 更年轻，部分 Electron 周边工具链无法直接使用。

**约束：**
- 现有 `main.js` 中的 presence/订阅逻辑需从主进程迁移至前端 JS，是迁移中最主要的改动点。

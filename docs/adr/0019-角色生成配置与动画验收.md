# ADR-0019：角色生成配置、坐标保留与分阶段验收

- 状态：已采纳
- 日期：2026-09-18
- 关联：演进 ADR-0009 的技能生成约束；不改变运行时互动协议。

## 背景

生成技能将像素风与四足动物动作作为通用约束，且闲置变体需要修改共享 Python 源码；逐帧包围盒裁剪并居中会消除腾空、贴贴等真实位移。机器检查完成后立即打包，也无法区分文件合格与视觉验收。

## 决策

- 保留 14 个必需状态的语义、时序预设、道具与互动方向，画风改为角色级配置。ADR-0009 中“像素风道具”演进为与角色风格一致、不透明、可干净抠图的道具；不新增第二角色。
- 角色配置记录身份、已有身体结构、性格、表演习惯、道具及状态动作补充说明。根据已有身体转译动作，不为执行动作增加器官。
- 闲置动作从固定共享选择改为运行级选择，允许符合运行时 `idle-*` 命名的自定义动作；准备阶段将状态规格冻结在请求文件，所有处理脚本读取同一份规格。
- 默认按完整等宽槽位统一缩放，保留帧内位置与透明运动空间；旧的逐帧居中模式仅作为显式兼容选项。
- 先生成基础形象、idle 和一个代表性困难状态，再生成剩余状态。默认每状态最多两次修复，耗尽后重新评估方案。
- 机器处理输出联系表、GIF 与动态预览，不代表完成。视觉审查记录绑定请求及 GIF 哈希；当前产物通过审查后才允许打包，测试合成素材禁止交付。
- 资源打包与项目安装分别报告；安装需检查 `public/pets/<id>/`、注册表及运行时行为，不自动改变用户账号或默认角色。

## 后果

不同身体与风格可共享技术契约，生成过程不再通过共享源码切换角色；更容易保留动作表达并追溯修复。运行配置与审查增加少量产物，但减少跨运行污染和误报完成。

稳定槽位依赖源图遵循布局，不能自动修复错位源图；GIF 仍限制软透明和复杂材质。确定性测试不能证明美观或动作趣味，真实生成质量需通过多类型角色的视觉评估持续验证。

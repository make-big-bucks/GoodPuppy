# ADR-0010：离线调色板换肤（颜色皮肤）

- **状态**：已采纳
- **日期**：2026-06-11

## 背景

宠物动画是一组索引调色板的像素 GIF（`public/pets/<id>/*.gif`），用户希望自定义"皮肤颜色"（如樱花粉、天蓝），且只改**狗主体的毛色**，鼻子、眼睛、黑描边、白肚皮以及 `feed`/`enter`/`leave` 等状态里的道具（食盆、木门）都要保持原样。

约束：

- 不引入前端框架/重运行时（见 [ADR-0004](0004-前端-webview-承担业务逻辑.md)）；
- 透明桌宠：换色不能破坏 alpha 透明；
- 资源事实属于各 pet（见 [ADR-0008](0008-分层动画状态机与实时事件.md)），不应把皮肤硬编码进 app 逻辑。

候选方案：

1. **CSS 滤镜 `hue-rotate`**：实时但整体偏色，无法只改毛色、无法精确控明度，像素画质差。
2. **运行时 canvas 逐帧重绘**：支持任意取色，但要把 `<img>` 改成 `<canvas>`、自管帧循环，重构成本高。
3. **离线调色板替换 + 预渲染变体**（采纳）：构建期从一套基础 GIF 派生出若干套变体，运行时仍是 `<img src>`，零成本。

## 决策

**构建期离线生成 + 运行时静态切换。**

- 生成器 `tools/generate-skins.mjs`（`npm run gen:skins`）逐帧解码为 RGBA，仅对"毛色像素"在 HSL 空间改色相/饱和度、尽量保留明度（即保留高光阴影层次），再用 gifenc 重编码，沿用原帧时长与透明。配置在 `tools/skins.json`。
- **道具排除**靠「参考调色板」：从一组**无道具的状态**（idle/happy/sad… 由 `fur.referenceStates` 指定）采集出狗身真实用到的毛色集合，重着色时只动「颜色落在该集合容差内」的像素；门/食盆不在集合里，自动放过。新增带道具的状态时**不要**把它列进 `referenceStates`。
- 产物落在 `public/pets/<id>/skins/<skinId>/<state>.gif`；基础橙色即 `default`（资源在 pet 目录根，路径不变）。
- 每只 pet 支持哪些皮肤是「资源事实」，由 `pet.json` 顶层 `skins: [{id,label}]` 声明，运行时随 manifest 加载。
- 运行时：`getStateImagePath(petId, state, skin)` 给非 default 皮肤拼 `skins/<id>/` 前缀；`PetAnimator` 持有 `skin` 字段并提供 `setSkin()`。皮肤选择是**纯本地偏好**，存 `localStorage`（不入 Supabase，避免 schema 变更），进房后经 presence payload 的 `skin` 字段广播，使房间内他人渲染我所选皮肤。右键菜单"换肤"子菜单从 manifest 的 skins 构建。

## 后果

正面：

- 运行时零成本，沿用既有 `<img>` 渲染与三层状态机，改动面小；
- 毛色明暗层次保留，道具/五官不被误染；
- 加新颜色只需在 `tools/skins.json` 加一项并重跑脚本；加新 pet 的皮肤只需各自 `pet.json` 声明 + 跑脚本。

负面 / 注意：

- 每套皮肤 = 整套 GIF 副本（shiba 16 态约 0.9MB/套），磁盘与仓库体积随皮肤数线性增长；
- 基础动画更新后须重跑 `gen:skins` 重新派生；
- 皮肤偏好仅存本地，换设备不跟随（如需跨端，后续可加 `profiles.skin` 字段，另立 ADR 并更新 `docs/database.md`）;
- 重着色质量依赖毛色与道具/背景的色相可分性；色相重叠严重的新形象可能需要调 `fur` 参数或人工产出变体。

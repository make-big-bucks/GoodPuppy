# ADR-0015：鼠标穿透由原生独占，webview 下发命中形状

- 状态：已采纳
- 日期：2026-06-18
- 关联：[ADR-0004：前端 webview 承担业务逻辑](0004-前端-webview-承担业务逻辑.md)、[ADR-0013：多窗口独立桌宠与协调者模型](0013-多窗口独立桌宠与协调者模型.md)

当前实现：点击与穿透共用原生成功接收的掩模，边缘容错编码进网格（按格宽向外取整）；每格采样覆盖像素的最大 alpha，避免漏掉细小轮廓。形状发布保持单次在途、成功后去重，失败后重试。

## 背景

透明置顶桌宠靠 `ignoreMouseEvents`（窗口级布尔）实现「pet 上可点、空白处穿透到背后 App」。原实现里这个决策放在前端：原生光标监视器每 16ms 把光标坐标 `emit` 给 webview → webview 做 canvas 像素命中 → 调 `setIgnoreCursorEvents`（再一趟 IPC 回原生）。

问题：**当穿透为 `true` 时 webview 收不到任何 DOM 鼠标事件**，唯一能把它翻回 `false` 的就是这条「轮询 + 两趟 IPC」链，约 30–50ms 延迟。用户在「光标刚进入 pet」这段延迟里点击，mousedown 会从窗口穿过去 → 没有 `pointerdown` → 拖不动。表现为「头一两下点不动、要多试几次」。本质是：一个原生窗口属性的决策被放在前端，逼出逐帧 IPC 往返。

## 决策

**鼠标穿透改由原生光标监视器独占，按轮询频率本地判定，无逐帧 IPC 往返。** webview 只在「可交互形状变化时」下发一次命中形状：

- 新增 `set_pet_hit_shape` 命令：webview 下发本窗口的可交互形状（窗口内容区 CSS 逻辑像素坐标）：
  - **pet 剪影 alpha 掩模**（`buildAlphaMask`，复用 `hitTesting.ts` 的 object-fit / 翻转 / alpha 阈值逻辑，保证与逐事件像素命中一致）；
  - **始终可交互的矩形**（可见气泡 / 输入条）；
  - **拖动强制位** `forceInteractive`（拖动期间整窗可交互，防光标滑出剪影中断拖动）。
- 原生监视器每 tick：算光标在各 pet 窗口内容坐标 → `shape_is_interactive`（纯函数，已单测）→ 直接 `set_ignore_cursor_events(!interactive)`，按窗口去重只在翻转时调用。
- 下发时机：动画帧/缩放/气泡显隐/输入条/布局/拖动等结构性变化即时下发（合并到一帧），外加 ~120ms 周期重发以跟上 GIF 自播放的剪影变化；窗口隐藏时跳过。

「可交互」延迟降到 ≤1 个轮询周期（≤16ms）、确定性，第一下即可点中拖动。

## 影响

- 删除前端反应式穿透回路：`cursorEventsController`（含其单测）、`cursor-moved` 事件与 `bridge.onCursorMoved` / `setIgnoreMouseEvents`。穿透只剩**单一所有者（原生）**，不再有「前端与原生各改同一窗口属性」的状态副本与潜在打架——更稳定、更少补丁。
- `petPresenter` 仍保留逐事件像素命中（`isPetOpaqueAt`）用于「是否真的起拖 / 右键」，与下发的掩模同源，精度一致。
- 气泡 hover 高亮改由 DOM `mousemove` 驱动（窗口可交互时本就收得到事件）。
- 命中形状走 IPC 的频率从「每次光标移动」降到「形状变化 + ~120ms 周期」，数据量小（掩模约几十×几十格）。
- 跨平台：判定是纯逻辑，应用走 Tauri `set_ignore_cursor_events`（macOS / Windows 通用），不依赖平台专有调用。

## 备选与权衡

- **矩形包围盒代替像素掩模**：改动更小，但 pet 包围盒的透明角落会变成可交互（不再穿透）。选了像素掩模以保留原有剪影精度。
- **保留前端所有权、只加原生「急切置可交互」**：会形成两个所有者改同一属性、状态易不同步，正是要避免的「补丁式」做法，排除。

# ADR-0018：会客厅设置页集中偏好与账号管理

- **状态**：已采纳
- **日期**：2026-06-21

## 背景

桌宠的可调偏好（朋友摆放模式、桌宠大小）此前只藏在桌宠的右键菜单里，发现性差且无集中入口；
账号相关操作（退出登录、匿名账号绑定邮箱）则散落在会客厅侧边栏的图标按钮上，语义不清——
侧边栏那颗「齿轮」按钮在登录后被运行时替换成「退出登录」，与图标含义不符。

需要一个正经的设置入口，把这些偏好与账号操作集中管理，并为「开机自启动」等系统级开关留出位置。

## 决策

1. **入口**：会客厅侧边栏齿轮恢复为「设置」入口；未登录不提供该入口（退出登录、绑定邮箱已收进设置页）。
2. **形态**：方案 A——整窗内视图切换。点齿轮隐藏房间布局（`.layout`），显示 `.settings-view`（跨满
   `app-window` 网格），左上「← 返回」切回。不新增 Tauri 窗口，契合「业务逻辑在前端、主进程薄层」原则
   （见 [ADR-0004](0004-前端-webview-承担业务逻辑.md)）。
3. **分组**（单页分组滚动）：
   - **桌宠**：朋友摆放模式（自由摆放 / 自动排布）、桌宠大小（滑块）。
   - **通用**：开机自启动。
   - **账号**：邮箱（匿名账号显示为「绑定邮箱」按钮，否则只读展示邮箱）、退出登录。
4. **右键菜单瘦身**：桌宠右键菜单移除「大小」「朋友摆放」两项（已迁入设置页统一管理）；换肤保留。
5. **跨窗口数据流**：桌宠偏好由 `main` 桌宠窗口消费。设置页（会客厅窗口）写入 localStorage 保证持久化
   （即便 `main` 尚未生成），同时 `emitTo("main", PET_PREF_MODE | PET_PREF_SCALE)` 实时应用；`main` 的
   监听调用既有 `coordinator.setMode` / `setPetScale` 并再次落盘（幂等）。
6. **开机自启动**：引入 `tauri-plugin-autostart`（macOS LaunchAgent / Windows 注册表，插件封装平台差异），
   在 `bridge` 中以动态 import 封装，非 Tauri 环境降级为 no-op；会客厅 capability 放行 enable/disable/is-enabled。

## 后果

- 正面：偏好可发现性提升、账号操作语义清晰；新增系统级开关有了落点；右键菜单更聚焦于「就地快捷操作」。
- 正面：跨窗口遥控以「localStorage 落盘 + emit 实时应用」双保险，`main` 缺席时偏好不丢。
- 负面：新增一个 Rust 插件依赖与一处 npm 依赖（`@tauri-apps/plugin-autostart`）。
- 负面：设置页与右键菜单不再有重叠项，习惯右键改大小/摆放的用户需改用设置页。

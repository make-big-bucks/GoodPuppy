# ADR-0009：互动双角色动画、idle 变体机制与运行时镜像

- 状态：已采纳
- 日期：2026-06-10
- 关联：演进 [ADR-0008](0008-分层动画状态机与实时事件.md) 的基础层与互动路由设计（三层优先级模型本身不变）

## 背景

ADR-0008 落地后，实际体验暴露出几个问题：

1. **基础层成员过于特殊化**：`wander` / `sit-stand` 是写死的两个「鲜活」状态，所有形象共享同一套花样，无法 per-pet 差异化。
2. **互动只有单侧动画**：贴贴只有发起者动、踢飞/喂食只有目标动，另一方毫无反应，互动感弱。
3. **进出场表达平淡**：`enter-run`（跑入）与 `leave-thrown`（抛飞）缺乏「从哪来、到哪去」的舞台感。
4. **拖动动画方向相关**：`drag-trot`（贴地小跑）有左右朝向，与任意方向的拖动不符。
5. **各状态动画区分度小**：缺少独立的视觉锚点（道具、场景元素）来彰显状态差异，而生成 skill 的全局规则又禁止一切分离元素。

## 决策

### 1. 基础层：idle + per-pet 变体（取消 wander / sit-stand）

基础层只保留 `idle` 一个固定成员。「鲜活」表现改为 **idle 变体机制**：

- 命名约定 `idle-<verb>`（如 `idle-stretch`、`idle-shake`）即合法变体，属于 pet.json 的**资源事实**，不进 `animationCatalog` 的行为表；`getBehavior()` 对该命名模式兜底返回 `{ layer: BASE, kind: "variant" }`。
- `PetAnimator` 从 manifest 收集变体：idle 停留 6–14s 后随机播一个变体（时长取自 manifest，一次性），播完回 idle；**没有变体就不起定时器**。
- skill 侧维护一个固定规格的变体候选池（stretch / shake / sniff / tail-chase / scratch），每次孵化默认选 2 个生成。池内规格固定保证稳定生成，选择不同保证 per-pet 花样不同。

### 2. 互动：双角色路由（取代单角色原则）

`INTERACTIONS` 从 `{ state, animates }` 改为 `{ actorState, targetState, mirror?, holdMs? }`，双方各播自己的动画：

| 互动 | 发起者 | 被作用者 |
|---|---|---|
| 贴贴 cuddle | `cuddle`（贴向自己画格右缘） | `cuddle`（镜像后贴左缘，两只贴在一起） |
| 喂食 feed | `cast`（挥魔法棒施法，新增状态） | `feed`（食物包出现在面前并被吃掉） |
| 踢飞 kick | `cast`（与喂食共用） | `kicked`（不变） |

`holdMs` 用于 loop 型瞬时动画（如 cuddle）的持续时长，避免只播一个循环周期。

### 3. 运行时镜像按「本端布局方位」而非角色

cuddle 基准 GIF 只生成「贴向右」一份；需要朝左时由 app 给 `<img>` 加 `scaleX(-1)`。**翻转与否由对方在本端布局中的左右方位决定**（`mirror: "facing"`），不能按 actor/target 角色定——每个端自己的 pet 都固定排在最左（index 0），按角色翻会在对方屏幕上贴反方向；按方位判定则任何端（含旁观者）看到的双方都是面对面。`PetAnimator.playTransient` 接受 `mirrored` 并经 `onState` 元数据透传给渲染层。

### 4. 进出场改为门、拖动改为拎起

- `enter`（替代 enter-run）：首帧只有一扇像素门，pet 逐帧从门中走出，门消失，末帧近似 idle 姿势以平滑衔接。
- `leave`（替代 leave-thrown）：pet 走入门中逐帧消失，末帧只剩门。
- `drag-lift`（替代 drag-trot）：被无形之手拎起、四肢悬空扭动，正面/对称 3/4 视角，方向无关。
- `busy` 重做表达：伏在贴身像素小桌/笔记本前埋头敲打、半转身不抬头的「专注勿扰」感。
- `message` 重做表达：叼起像素纸飞机扬头掷出。

### 5. skill：按状态声明的道具白名单

不放宽全局「禁止分离元素」规则，改为 **per-state 道具白名单**（`STATE_REQUIREMENTS`）：门（enter/leave，允许某帧只有门）、食物包（feed，前几帧可与 pet 分离）、纸飞机（message，仅末 1–2 帧可脱离）、魔法棒（cast，始终握持）、小桌（busy，始终贴身）。道具必须不透明、硬边、像素风、不越帧槽。含大道具的状态（enter/leave/feed/message）帧提取默认用等宽槽位切割而非连通组件归组，避免道具归错帧。

## 后果

**正面：**

- 互动双方都有反馈，贴贴在两端及旁观者视角都正确面对面。
- 「鲜活」表现成为 per-pet 可配置的资源事实，新增变体零代码改动（pet.json 加一个 `idle-*` 状态即可）。
- 门/道具给各状态提供独立视觉锚点，状态区分度显著提升，且通过白名单机制保持稳定生成约束。
- 拖动动画方向无关，消除朝向违和。

**负面 / 约束：**

- 必备状态集变化（删 wander/sit-stand/drag-trot/enter-run/leave-thrown，增 cast/enter/leave/drag-lift），旧资源包不兼容，需按新 skill 重新孵化；过渡期以旧 GIF 重命名占位（`cast` 暂用 greet 资源）。
- CSS 镜像期间像素级命中测试左右颠倒（cuddle 约 3s），影响可忽略，未做补偿。
- cuddle 双方各贴自己画格边缘，dog-area 间距会留缝；如需收拢由后续 CSS 处理。
- 镜像判定依赖 `petLayout` 的布局顺序；若未来布局可自定义排序，`facing` 判定自动随布局生效。
- broadcast 事件协议（`{ action, actorId, targetId }`）与 presence payload 不变，无线上兼容问题。

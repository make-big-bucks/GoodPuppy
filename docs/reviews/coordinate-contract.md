# 多显示器坐标修复依据

对应验收项 20，仍未完成。依据当前依赖 Tao 0.35.3 的 `platform_impl/{macos,windows}/{window,monitor}.rs`，不能把两平台的 `PhysicalPosition` 当作同一种全局平面。

| 当前 API | macOS 实现 | Windows 实现 |
|---|---|---|
| 窗口 outer_position | AppKit 全局逻辑位置 × 当前窗口比例 | GetWindowRect 全局物理位置 |
| 窗口 LogicalPosition 写入 | 除当前窗口比例后写 AppKit 逻辑位置 | 乘当前窗口比例后 SetWindowPos |
| 显示器 position | CGDisplayBounds 逻辑原点 × 该屏比例 | 显示器全局物理原点 |

因此，macOS 各屏除各自比例能恢复同一逻辑平面；Windows 逐屏除比例会让矩形重叠，窗口跨屏后自身比例变化也会改变同一物理位置的数值。单次主线程几何快照包含比例，气泡读取实际父窗口外框以避免预测尺寸偏差；它解决读取时序，实际父窗口选屏解决误选屏，均未解决 Windows 全局单位混用。

父子跟随已改为 Windows 全局物理/macOS 全局逻辑单位，偏移由成功定位后的实际位置计算；比例不同/变化的换算回归与 macOS 原生回归通过，Windows 实机仍待验收。

完整修改仍必须覆盖：

- 桥接位置/尺寸/屏幕/工作区 DTO：区分桌面坐标、窗口局部逻辑尺寸和比例，平台转换集中在原生边界。
- 创建、定位和父子跟随：目标位置不能依赖创建前窗口所在屏的比例，偏移需与父窗口位置使用同一单位。
- 房间自动布局、气泡避让、光标屏提醒：逻辑内容尺寸进入桌面布局前按目标屏转换。
- 位置存档：已写入 `window-logical-v1` 单位版本、拒绝未知版本，旧无版本值仍按旧契约读取；迁移到新坐标时必须显式处理，不能直接解释为新单位。

实现门禁：负原点、主副屏不同缩放、两方向跨屏、气泡跟随/翻转、提醒定位、拔屏及旧存档恢复。最终需要 macOS 与 Windows 的实际多屏证据，模拟换算不能替代实机验收。
